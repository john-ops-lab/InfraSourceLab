# 安全与许可证边界

> **状态：现役安全与许可证边界。**
>
> 本文描述当前安全边界与适用环境；具体实现与验证状态见 [`status.md`](status.md)。默认凭据只适用于本机或可信内网，公网部署前必须自行更换并补充防护。

## 1. 威胁模型

InfraSourceLab 用于：

- 本地或可信内网；
- 单用户；
- 生成测试数据；
- 一个普通 Web 和 API 应用；
- 默认只对本机开放。

它不是：

- 公网 SaaS；
- 多租户系统；
- 容器执行平台；
- 任意脚本平台；
- 企业身份管理系统。

安全措施要覆盖真实风险，但不能把首版拖成安全平台建设。

## 2. API 认证

计划配置：

```text
ISL_API_KEY=<secret>
```

所有 `/api/v1/*` 模板、规格、数据集、数据、删除和导出接口要求：

```http
Authorization: Bearer <ISL_API_KEY>
```

要求：

- 使用安全字符串比较；
- 缺失或错误时返回 401；
- 日志不记录完整 Key；
- 错误响应不回显 Key；
- `.env` 不提交 Git；
- `.env.example` 只放占位符；
- Docker Compose 默认只发布到 `127.0.0.1`。

`GET /health` 可以不认证。

FastAPI `/docs` 是否认证可根据实现成本决定，但必须文档说明，不能为此建设复杂中间件体系。

## 3. 前端中的 API Key

前端可以让用户录入 Key，随后附加到请求头。

允许：

- 仅保存在内存；
- 保存在 `sessionStorage`。

不允许：

- 写入源码或构建产物；
- 放进 URL 查询参数；
- 发送给 AI；
- 打印到 Console；
- 回显服务端环境变量真值；
- 默认长期保存在 `localStorage`。

## 4. AI Provider 凭据

```text
ISL_AI_BASE_URL
ISL_AI_API_KEY
ISL_AI_MODEL
ISL_AI_TIMEOUT_SECONDS
```

要求：

- 只在后端读取；
- 不返回浏览器；
- 不写普通日志；
- Provider 错误要简化和脱敏；
- 请求设置超时、输入长度和响应大小限制；
- 自动化测试使用假 Provider。

AI 只返回 `GenerationSpec` 建议，不能访问数据库、文件系统、命令行或运行环境，也不能直接创建数据集。

## 5. 输入安全

MVP 外部输入主要包括：

- 提示词；
- `GenerationSpec` JSON；
- 查询参数；
- 数据集名称；
- 导出格式。

必须计划实现：

- Pydantic 权威校验；
- 提示词和请求体大小上限；
- 单类 CI 数量和总数量上限；
- 字符串长度上限；
- 自定义字段数量和嵌套深度上限；
- `page_size` 上限；
- 导出格式白名单；
- 稳定且有限的错误响应；
- `q` 搜索只查询受控 `search_text`；
- `%`、`_` 和转义字符按普通文字处理，不能无意成为 SQL 通配符。

首版不接受 YAML、压缩包、HAR、任意文件上传或 URL 导入，因此不需要为这些未实现能力建设清洗管道。

## 6. 禁止任意执行

`GenerationSpec` 不允许包含：

```text
命令行指令
Python 或 JavaScript
Jinja 表达式
Docker 镜像
宿主机路径
SQL 片段
任意 URL 回调
插件包
```

自定义类型最多只允许有限、安全、JSON 兼容的字段生成规则。

## 7. 数据库与事务

SQLite 文件计划放在受控数据目录。

要求：

- 不把 API Key 或 AI Key 写入数据集；
- 删除数据集时只删除其对应记录和关系；
- 生成失败时不留下伪成功数据集；
- 发布前校验所有关系引用；
- 相同 `(dataset_id, type, from_ci_id, to_ci_id)` 的关系必须唯一；
- SQLAlchemy 使用参数化查询；
- API 不暴露任意 SQL 或 JSON 路径查询；
- 内部 `search_text` 只由字段白名单生成，不暴露给 API；
- 使用 `PRAGMA user_version = 1` 识别数据库模式；
- 发现未知非零版本时拒绝启动并给出明确备份、删除和重建提示，不能静默改表。

本地工具不需要数据库加密集群、高可用或复杂备份系统。用户备份 SQLite 文件即可。

Issue #1 和 #2 都不建设自动迁移链。未来真实升级需要保留旧数据时再单独立项。

## 8. 导出安全

- 文件名由数据集 ID 或安全短名称生成；
- 导出格式使用白名单；
- 不接受用户指定任意输出路径；
- 临时文件放在受控目录并及时清理；
- CSV 和 XLSX 对以 `=`、`+`、`-`、`@` 开头的用户可控单元格考虑公式注入转义；
- 导出不包含 API Key、AI Key 或内部 `search_text`。

## 9. 网络

宿主机默认只发布：

```text
127.0.0.1
```

应用在容器内可以监听 `0.0.0.0` 以支持端口映射，但 Compose 默认必须使用类似：

```text
127.0.0.1:8080:8080
```

用户主动对局域网或公网开放时，应明确提示：

- 使用强 API Key；
- 放在受控网络或反向代理后；
- MVP 不承诺公网多用户安全。

不需要 Docker socket、特权容器、宿主网络或远程 Agent。

## 10. 日志

可以记录：

- 接口路径；
- 数据集 ID；
- 数量；
- 耗时；
- Provider 状态和错误类别；
- SQLite 模式版本错误类别。

不能记录：

- Bearer Token；
- AI API Key；
- 默认完整提示词；
- 完整大数据集；
- Authorization 请求头；
- 浏览器会话 Key；
- 用户原始搜索词全文（默认）。

## 11. 依赖与许可证

InfraSourceLab 自有代码采用根目录 **Apache License 2.0**。

Issue #1 第三方依赖要求：

- 使用正常包管理锁定文件；
- 记录主要依赖版本；
- 不复制许可证不明的源码；
- shadcn/ui 组件按其正常使用方式进入项目；
- Faker、Mimesis 和 XLSX 库在实施时核对当时的许可证；
- Issue #1 不引入 assistant-ui；未来若因多轮交互单独引入，再核对当时的版本和许可证。

首版不建设大型软件物料清单或供应链平台；基础依赖扫描和许可证检查放入 CI 即可。

## 12. 不建设的安全系统

MVP 明确不做：

- 用户注册和登录；
- RBAC；
- OAuth、OIDC 或 SSO；
- API Key 数据库和权限范围；
- mTLS Agent；
- Docker 沙箱；
- 多租户隔离；
- 审批工作流；
- 企业审计平台；
- WAF 或公网防护方案；
- 自动数据库迁移平台。

如果未来部署模式变化，再根据新的真实威胁模型建立范围明确的 Issue。

## 13. MVP 安全验收

当前审查重点需要证明：

1. 无 Key 的 `/api/v1/*` 接口返回 401；
2. 正确 Key 可以调用；
3. Key 不出现在日志、URL、导出和 AI 请求中；
4. AI Key 只在后端；
5. 规格、数量、分页和请求体都有上限；
6. 不存在任意执行字段；
7. SQLite 操作和删除不会越界；
8. `q` 只搜索白名单 `search_text` 并正确转义通配符；
9. `PRAGMA user_version` 对未知版本明确拒绝；
10. 导出路径和格式安全；
11. 默认只对本机发布端口；
12. 不使用 Docker socket 或特权运行环境。

通过这些与本地部署相匹配的检查即可，不因未来可能公网化而阻塞 MVP。

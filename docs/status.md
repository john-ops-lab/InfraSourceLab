## 状态判断规则

只有同时满足以下证据，才能把项目状态改为“已实现”或“待审查”：

1. `main` 中存在实际产品代码；
2. 有明确的实现提交范围；
3. 能从 GitHub 重新拉取并运行；
4. 自动化测试命令和结果可复现；
5. 浏览器主流程有真实验证证据；
6. Issue 中记录了准确的起始提交、结束提交、已知限制和验证结果。

没有这些证据时，不得声称功能已开发、测试通过或可以进行代码审查。

## 当前权威顺序

发生冲突时，按以下顺序判断：

1. GitHub `main` 中实际存在的文件和提交；
2. 本状态文档；
3. 开放的 Issue #1 和 #2；
4. 其他设计文档；
5. `docs/research/` 中的历史调研。

历史聊天记录、未关联到分支的 Git 对象、临时工作目录或未提交代码都不代表仓库当前状态。

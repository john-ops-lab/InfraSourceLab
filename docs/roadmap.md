# InfraSourceLab 精简路线图

> **当前版本：v0.1.1，项目进入小步维护阶段。**

## 1. 已完成的产品闭环

```text
自然语言或模板
→ 经过校验的 GenerationSpec
→ 确定性生成 CI 与关系
→ Bearer Token REST API
→ JSON / CSV / XLSX 导出
→ 拓扑浏览与数据质量缺陷注入
→ 规格下载/导入/复用、精确质量报告与简单一对多关系
```

Issue #1 的 MVP 与 Issue #2 的拓扑、数据质量、CMDB 使用示例均已进入 `main`。当前实现与测试数量以 [`status.md`](status.md) 为准。

## 2. 当前维护原则

后续工作来自真实使用反馈，优先级依次是：

1. 修复会产生错误数据、错误搜索结果或误导性界面的正确性问题；
2. 保持生成结果可复现、关系无悬空引用、搜索索引与记录内容同步；
3. 保持大数据集接口有界，并让拓扑抽样优先保留可见关系；
4. 保持内置模板依赖的 CI 类型和关系类型可用；
5. 让代码、测试、用户文档和 CI 对同一事实给出一致答案。

所有改动通过独立分支和 Pull Request，后端、前端、构建与端到端 CI 通过后再合并。

## 3. 按需评估的未来方向

只有出现明确的用户流程或兼容需求时，才单独建立 Issue 评估：

- PostgreSQL 或 SQLite 数据迁移；
- 后台生成任务与更大数据规模；
- 多 API Key 或公网认证；
- 多轮 AI 创建交互；
- 单个明确的协议、服务或导入格式适配器。

新增前必须回答：现有 REST API 或文件导出为什么不够，以及最小改动能否解决问题。

## 4. 明确不做的平台化方向

Issues #3～#8 已关闭为“不计划实施”，当前不建设：

- 生命周期、故障注入与自动验证平台；
- 多协议模拟器套件；
- 云与管理协议模拟器套件；
- 企业真实服务编排与录制回放平台；
- 高级 AI 导入与通用工具平台；
- 分布式运行、远程代理与大规模发布平台。

这些方向只有在出现具体、可验证的真实需求时才重新评估。
